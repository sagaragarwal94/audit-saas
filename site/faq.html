Frequently asked questions

What is AuditSaas?

A local CLI that scans a codebase for security, privacy, AI-abuse, payments, and production-readiness gaps — the kind of issues AI coding assistants (Cursor, Claude Code, v0, Lovable, Bolt, etc.) tend to skip. It runs 65 rules across 23 categories and writes the results as Markdown and JSON reports directly into your project.

Does my code ever leave my machine?

No, not by default. The core scanner reads your files locally and never makes a network call. The only exception is the optional AI second-pass review, which is off unless you explicitly configure it — and even then you can point it at a local model (Ollama, LM Studio) instead of a hosted API, so nothing has to leave your machine even with AI review on.

How do I install it?

npx github:sagaragarwal94/audit-saas scan . — no install step (the project has zero runtime dependencies). Or clone the repo if you want to contribute: git clone https://github.com/sagaragarwal94/audit-saas && cd audit-saas && npm install.

What does it actually check?

Auth (password hashing, login rate limits, session expiry, cookie flags), authorization/IDOR, API validation, SQL injection and XSS, secrets exposure, CORS/SSRF/CSRF, JWT misconfiguration, dependency and supply-chain risk, file upload handling, admin/debug surface exposure, infra misconfiguration, Stripe webhook signature and idempotency checks, AI/LLM cost and prompt-injection exposure, and privacy/data-collection inventory with policy drafting. See the rule catalog for examples.

Is it free?

Yes. AuditSaas is free to use under the Functional Source License described above — the only thing you can't do is turn it into a competing commercial product.

Will this replace a real security audit or pentest?

No. AuditSaas is a fast, automated first pass that catches common, well-understood mistakes before they ship. It's a complement to (not a replacement for) a professional security review, especially for anything handling sensitive data at scale.

I think a finding is wrong (false positive/negative) — what do I do?

Open an issue on GitHub or reach out at hello@auditsaas.org with the rule ID and a bit of context. False-positive reports directly shape what gets fixed next — see Feedback & feature requests.

I found a security issue in AuditSaas itself — how do I report it?

See our security and disclosure page for how to report it responsibly.

What frameworks and stacks does it understand?

Today: JavaScript and TypeScript, full depth. It auto-detects common SaaS stacks — Next.js/Remix/Express/Fastify, Clerk/NextAuth/Supabase Auth/Firebase Auth, Prisma/Drizzle/Supabase/Mongo/Postgres/MySQL, Stripe/Paddle/Lemon Squeezy, OpenAI/Anthropic/Gemini/LangChain/Vercel AI SDK, and Docker/Terraform infra — then only runs the relevant rules.

Python, Java, Kotlin, Swift, Rust, Go, and native Android/iOS checks are on the roadmap, prioritized by community demand rather than shipped speculatively.
