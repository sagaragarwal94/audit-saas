What's new

October 2026 — v0.2.0

  • Real evidence in every finding: reports now show the actual line of your code that matched, with the file and line, instead of the detector's pattern. Secrets, .env values, and credentials inside connection strings are redacted before anything is written.
  • CI gating: --fail-on high exits non-zero when findings meet the threshold, --json prints machine-readable output, and invalid flags or values exit with code 2 instead of being silently ignored.
  • Suppressions and config: use // auditsaas-ignore RULE_ID -- reason inline, auditsaas-ignore-file for a whole file, or .auditsaas.json with ignorePaths, ignoreRules, failOn, and focus. Suppressed findings stay listed in the report.
  • Baselines: --baseline findings.json reports only new findings. Fingerprints are keyed on the matched code, not line numbers, so they survive unrelated edits.
  • Better SARIF: stable fingerprints, GitHub security-severity scores, rule help links to /rules, and project-wide findings anchored to package.json so code scanning doesn't drop them.
  • Far fewer false positives: Markdown docs no longer trigger code rules; SVG xmlns URLs aren't "insecure HTTP"; parameterized sql`...${id}` tagged templates aren't SQL injection; reading a cookie isn't treated as setting one; login/webhook routes aren't flagged for missing auth; middleware-based auth lowers confidence; Stripe-publishable/Supabase-anon/Firebase keys aren't "exposed secrets"; placeholder keys and AWS's documented example key are ignored. The data inventory no longer counts README prose or matches ip inside words like "script".
  • Caught what it used to miss: weak password hashing and missing login rate limits in route handlers outside an auth/ folder; frontend secret exposure through VITE_, EXPO_PUBLIC_, REACT_APP_, NUXT_PUBLIC_, and PUBLIC_ variables; Anthropic, GitHub, and Slack tokens and private-key blocks; compose.yaml, bun.lock, gzipped SQL dumps; and .vue, .svelte, and .astro files.
  • Robustness: unreadable directories, binary files, and symlinks no longer crash or derail a scan; a failing detector is reported and skipped; --url checks follow redirects (http→https counts as HTTPS) and time out after 15s; the AI review times out, retries models that reject temperature, and never blocks the deterministic reports.
  • New: a saas-audit rules command, an auditsaas binary alias, a --no-history flag, and a top-findings list in the terminal summary. Each rule on /rules now has a linkable anchor.
  • Claude Code skill: /audit-saas-review now traces auth and data paths across files, runs a verification pass before reporting, honors your suppressions, and reports what it covered and what it skipped.
  • CI: tested on Node 20, 22, and 24, and the scanner now scans its own repo on every push.

August 2026

  • Open sourced under the Functional Source License 1.1 (Apache-2.0 future grant) — the full rule catalog is public on /rules, contributions are open, and CI runs on every PR.
  • CI pipeline — tests run on Node 20.x/22.x on every push/PR, including a check that the markdown rule catalog and the JavaScript detectors never drift out of sync.
  • Fixed the rule count — a parser bug meant one of the "66" advertised rules was actually a bogus entry parsed out of the contribution guide's example text. The real, correct count is 65.
  • Closed 4 rules that had no detector — OPEN_REDIRECT_UNVALIDATED, MASS_ASSIGNMENT_RISK, API_RATE_LIMIT_MISSING_PUBLIC, and GRAPHQL_INTROSPECTION_ENABLED were documented but never actually implemented.

July 2026

  • Rule catalog grew to 65 rules across 23 categories (from 46/20) — added JWT expiration checks, non-cryptographic token randomness, OAuth CSRF (state parameter), unauthenticated WebSocket handlers, exposed Swagger UI and health-endpoint info leaks, npm install-time script risk, hardcoded cloud credentials, exposed backup files, public Terraform S3 buckets and open security groups, CSP unsafe-inline/eval, exposed production source maps, missing SRI on external scripts, Stripe client-trusted checkout amounts, unbounded list queries, GraphQL depth limiting, and unauthenticated Next.js Server Actions.
  • Light mode — a theme toggle in the nav, defaulting to your OS preference and remembered across visits.
  • Local-LLM AI review — point the optional AI review step at a local model server (Ollama, LM Studio) instead of a hosted API key.
  • SARIF export (findings.sarif.json) for GitHub code scanning and other CI tooling.
  • Reduced false positives from documentation, test files, and properly gitignored local .env files — behavior-based rules now scope to real application code.
  • FAQ, Privacy Policy, Terms, and Security/disclosure pages published ahead of public launch.
