The rule catalog

Every rule ships with a risk statement, recommendation, and standards mapping. Here's one example per severity — the full catalog is available to invited beta testers.

A sample of what's inside

SECRETS_ENV_COMMITTED

critical

Risk: Committed environment files can leak production credentials and third-party API keys.

Fix: Remove real .env files from version control, rotate exposed secrets, keep only .env.example.

AUTH_LOGIN_RATE_LIMIT_MISSING

high

Risk: Unthrottled login attempts allow credential stuffing and brute-force attacks.

Fix: Apply rate limits per IP and per account, track failed attempts, and add lockout/backoff controls.

AUTH_SESSION_EXPIRY_MISSING

medium

Risk: Long-lived or unbounded sessions increase impact after token theft.

Fix: Configure bounded session expiry, refresh-token rotation, and server-side logout invalidation.

SQL_INJECTION_RAW_QUERY

critical

Risk: String-built SQL can allow attackers to read, modify, or delete database data.

Fix: Use parameterized queries or ORM query builders.

PAYMENT_STRIPE_WEBHOOK_SIGNATURE_MISSING

critical

Risk: Attackers may forge payment events and unlock paid features or alter subscription state.

Fix: Verify signatures with the raw request body before processing events.

JWT_ALGORITHM_NOT_ENFORCED

critical

Risk: Verifying tokens without pinning the algorithm allows algorithm-confusion attacks.

Fix: Always pass an explicit algorithms allowlist to jwt.verify.

AI_FRONTEND_OR_UNBOUNDED

high

Risk: Unprotected AI calls can leak API keys, enable abuse, and burn API spend quickly.

Fix: Keep AI keys server-side and enforce per-user rate limits.

SSRF_UNVALIDATED_URL_FETCH

high

Risk: Fetching a URL built from request input lets an attacker reach internal services or metadata endpoints.

Fix: Validate outbound URLs against an allowlist of hosts.

MASS_ASSIGNMENT_RISK

high

Risk: Spreading the raw request body into a database write lets attackers set fields like role.

Fix: Explicitly allowlist the fields copied into writes.

CORS_WILDCARD_WITH_CREDENTIALS

medium

Risk: A wildcard origin combined with credentials lets any site read authenticated responses.

Fix: Use an explicit allowlist of trusted origins.

INFRA_DB_PORT_EXPOSED

medium

Risk: Publishing database ports beyond the internal network can expose data stores to the internet.

Fix: Remove public port mappings for data stores.
