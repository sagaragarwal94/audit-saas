The rule catalog

Every rule ships as plain Markdown with a risk statement, recommendation, and standards mapping. The detector logic lives in src/rules.js, keyed by the same rule ID. Contributions welcome.

Auth

AUTH_PASSWORD_HASHING_WEAK

critical

Risk: Weak password storage can lead to account takeover if the database is exposed.

Fix: Use Argon2id or bcrypt with a suitable cost factor, never plaintext or raw SHA/MD5 hashes.

AUTH_LOGIN_RATE_LIMIT_MISSING

high

Risk: Unthrottled login attempts allow credential stuffing and brute-force attacks.

Fix: Apply rate limits per IP and per account, track failed attempts, and add lockout/backoff controls.

AUTH_SESSION_EXPIRY_MISSING

medium

Risk: Long-lived or unbounded sessions increase impact after token theft.

Fix: Configure bounded session expiry, refresh-token rotation, and server-side logout invalidation.

AUTH_COOKIE_FLAGS_MISSING

medium

Risk: Cookies without HttpOnly, Secure, and SameSite controls are easier to steal or abuse.

Fix: Set HttpOnly, Secure, and SameSite=Lax or Strict for session cookies in production.

API & Authorization

AUTHZ_IDOR_POSSIBLE

critical

Risk: Users may access another user's or tenant's records by changing an ID in the URL or request body.

Fix: Scope every sensitive query by authenticated user, organization, or tenant in the database query itself.

API_AUTH_MISSING

high

Risk: Public API routes can expose data or trigger sensitive actions without a valid user session.

Fix: Require server-side authentication and authorization in every sensitive API route.

API_VALIDATION_MISSING

medium

Risk: Unvalidated input can lead to malformed data, injection risks, and unexpected behavior.

Fix: Validate request bodies with Zod, Valibot, Joi, Yup, or equivalent schema validation.

OPEN_REDIRECT_UNVALIDATED

medium

Risk: Redirecting to a URL taken directly from a query parameter can be used for phishing or to bypass OAuth allowlists.

Fix: Validate redirect targets against an allowlist of internal paths or trusted domains.

MASS_ASSIGNMENT_RISK

high

Risk: Spreading the raw request body into a create/update call lets attackers set fields like role or plan.

Fix: Explicitly allowlist the fields copied from request input into database writes.

API_RATE_LIMIT_MISSING_PUBLIC

medium

Risk: Endpoints without rate limiting are vulnerable to scraping, credential stuffing, and cost-driving abuse.

Fix: Add per-IP and per-account rate limiting to public-facing API routes.

GRAPHQL_INTROSPECTION_ENABLED

medium

Risk: Introspection lets attackers enumerate your entire GraphQL schema, including unexposed fields and mutations.

Fix: Disable introspection and the GraphiQL/Playground UI outside of development.

Database

SQL_INJECTION_RAW_QUERY

critical

Risk: String-built SQL can allow attackers to read, modify, or delete database data.

Fix: Use parameterized queries or ORM query builders. Never concatenate user-controlled data into SQL.

SUPABASE_RLS_NOT_CONFIRMED

medium

Risk: Without RLS policies, any authenticated or anonymous client can read or write every row in a Supabase table.

Fix: Enable Row Level Security and add explicit policies scoping access to the authenticated user or tenant.

Secrets

SECRETS_ENV_COMMITTED

critical

Risk: Committed environment files can leak production credentials and third-party API keys.

Fix: Remove real .env files from version control, rotate exposed secrets, keep only .env.example.

SECRETS_HARDCODED

critical

Risk: Hardcoded keys can be extracted from source code, logs, client bundles, or repo history.

Fix: Move secrets to server-side env vars, rotate exposed keys, add secret scanning to CI.

SECRETS_FRONTEND_PUBLIC_KEY

critical

Risk: Secrets in NEXT_PUBLIC_* vars or client components can be exposed to every browser user.

Fix: Never expose OpenAI, Stripe secret, Supabase service role, or private keys to frontend code.

CI_SECRETS_HARDCODED_IN_WORKFLOW

critical

Risk: Secrets committed inside a CI workflow file are visible to anyone with repo read access and remain in git history.

Fix: Reference secrets only through the CI provider's encrypted secret store.

XSS

XSS_UNSAFE_HTML

high

Risk: Rendering user-controlled HTML without sanitization can execute attacker-controlled scripts.

Fix: Avoid raw HTML rendering; if required, sanitize with a proven library and use a strict CSP.

Payments

PAYMENT_STRIPE_WEBHOOK_SIGNATURE_MISSING

critical

Risk: Attackers may forge payment events and unlock paid features or alter subscription state.

Fix: Use stripe.webhooks.constructEvent with the raw body and signing secret before processing events.

PAYMENT_IDEMPOTENCY_MISSING

high

Risk: Repeated webhook delivery can duplicate side effects or corrupt subscription state.

Fix: Store processed event IDs and make subscription updates idempotent.

AI

AI_FRONTEND_OR_UNBOUNDED

critical

Risk: Unprotected AI calls can leak API keys, enable abuse, and burn API spend quickly.

Fix: Keep AI keys server-side, require auth, enforce per-user/IP/tenant rate limits, cap tokens.

AI_PROMPT_INJECTION_REVIEW

medium

Risk: LLM features can leak sensitive context or execute unsafe tool actions if unconstrained.

Fix: Add prompt-injection mitigations, tool authorization checks, and data minimization.

Headers & Transport

HEADERS_HTTPS_RUNTIME

medium

Risk: Missing browser security headers increase exposure to XSS, clickjacking, and MIME sniffing.

Fix: Enforce HTTPS and configure HSTS, CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy.

CONFIG_HTTP_URLS

medium

Risk: Plain HTTP URLs can leak traffic and break secure cookie/OAuth/webhook expectations.

Fix: Use HTTPS for production URLs, OAuth callbacks, payment webhooks, and API integrations.

Logging & Monitoring

LOGGING_SECRETS_RISK

high

Risk: Logging tokens, passwords, or full payloads can create a secondary data breach path.

Fix: Redact secrets from logs; avoid logging bodies, auth headers, cookies, payment payloads, AI prompts.

MONITORING_ANOMALY_GAPS

medium

Risk: Without anomaly alerts, abuse can continue unnoticed after launch.

Fix: Alert on failed login spikes, repeated 401/403s, sequential ID access, AI spend spikes, webhook failures.

Privacy

PRIVACY_DATA_COLLECTION_FOUND

medium

Risk: Collected personal data, AI prompts, analytics, and payment metadata need clear disclosure.

Fix: Review the generated data inventory and publish a lawyer-reviewed privacy policy before launch.

PRIVACY_NO_DELETION_ENDPOINT

medium

Risk: GDPR/CCPA require a way for users to request deletion of their personal data.

Fix: Add an account deletion flow that removes or anonymizes personal data across all data stores.

PRIVACY_THIRD_PARTY_TRACKING_NO_CONSENT

medium

Risk: Loading analytics or session-replay scripts before consent can violate GDPR/ePrivacy requirements.

Fix: Gate non-essential tracking behind a cookie consent banner.

CORS

CORS_WILDCARD_WITH_CREDENTIALS

critical

Risk: A wildcard Access-Control-Allow-Origin combined with credentials lets any site read authenticated responses on behalf of a logged-in user.

Fix: Use an explicit allowlist of trusted origins instead of * whenever credentials are allowed.

CORS_ORIGIN_REFLECTED

medium

Risk: Reflecting the request Origin header back verbatim effectively disables CORS protection for every origin.

Fix: Validate the incoming origin against an explicit allowlist before echoing it back.

SSRF

SSRF_UNVALIDATED_URL_FETCH

high

Risk: Fetching a URL taken directly from request input lets an attacker make the server call internal services or cloud metadata endpoints.

Fix: Validate outbound URLs against an allowlist of hosts/protocols and block private/link-local IP ranges.

JWT

JWT_ALGORITHM_NOT_ENFORCED

critical

Risk: Verifying tokens without pinning the expected algorithm allows algorithm-confusion attacks, including forged alg:none tokens.

Fix: Always pass an explicit algorithms allowlist to jwt.verify.

JWT_SECRET_WEAK_OR_HARDCODED

critical

Risk: A hardcoded or short JWT secret can be brute-forced or leaked through source control.

Fix: Load the signing secret from environment variables with at least 32 bytes of entropy.

CSRF

CSRF_PROTECTION_MISSING

medium

Risk: State-changing requests authenticated only by cookies can be triggered from another origin.

Fix: Use SameSite cookies plus a CSRF token, or a framework's built-in CSRF middleware.

Dependencies & Supply Chain

DEPENDENCY_NO_LOCKFILE

medium

Risk: Without a lockfile, dependency versions can drift, pulling in unreviewed or vulnerable updates.

Fix: Commit a lockfile and install with a frozen-lockfile flag in CI.

DEPENDENCY_WILDCARD_VERSION

medium

Risk: Wildcard or latest version ranges can silently pull in breaking or malicious updates.

Fix: Pin dependencies to specific or caret-ranged versions.

DEPENDENCY_KNOWN_RISKY_PACKAGE

high

Risk: Some packages are deprecated, unmaintained, or have a documented history of supply-chain compromise.

Fix: Replace with actively maintained alternatives and run npm audit regularly.

File Uploads

UPLOAD_UNRESTRICTED_FILE_TYPE

high

Risk: Accepting any file type or size lets attackers upload executable scripts or oversized payloads.

Fix: Validate MIME type/extension against an allowlist and enforce a maximum file size.

UPLOAD_PATH_TRAVERSAL

critical

Risk: Writing a file using an attacker-supplied filename can overwrite arbitrary files via path traversal.

Fix: Generate a server-side random filename and write only inside a fixed upload directory.

Admin & Debug Surface

ADMIN_ROUTE_NO_ROLE_CHECK

critical

Risk: An admin-labeled route that only checks for a valid session can be reached by any authenticated user.

Fix: Require an explicit role/permission check in every admin route.

DEBUG_ENDPOINT_EXPOSED

high

Risk: Debug/internal endpoints often skip auth and can expose environment details or admin actions.

Fix: Remove debug/test routes before shipping or gate them behind auth and an environment check.

Infra

INFRA_DOCKER_ROOT_USER

medium

Risk: Containers running as root increase the blast radius of a container escape.

Fix: Add a non-root USER directive to the Dockerfile.

INFRA_DB_PORT_EXPOSED

high

Risk: Publishing database/cache ports beyond the internal Docker network can expose data stores to the internet.

Fix: Remove public port mappings for data stores in production compose files.

Code Execution

CODE_EXECUTION_EVAL_USER_INPUT

critical

Risk: eval, new Function, or child_process.exec near request input can allow full remote code execution.

Fix: Remove dynamic code execution entirely or sandbox it strictly.
