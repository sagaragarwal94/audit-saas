Built for apps that shipped fast

AI pair-programmers are great at features and terrible at the boring, load-bearing stuff. AuditSaas checks for exactly that.

Auth & authorization

Password hashing, login rate limits, session expiry, cookie flags, and IDOR-prone access checks.

API & injection

SQL injection and XSS patterns, unauthenticated endpoints, and unsafe request handling.

Secrets exposure

Committed .env files, frontend-bundled API keys, and hardcoded credentials.

AI & LLM abuse

Unbounded AI endpoints, missing rate limits on model calls, and prompt-injection exposure.

Payments

Stripe webhook signature verification and other payment-integration security gaps.

Privacy & production readiness

Data collection inventory, deletion/consent gaps, privacy-policy draft generation, security headers, and logging/redaction gaps.

Access & request forgery

CORS misconfiguration, SSRF-prone fetches, CSRF gaps, open redirects, and mass-assignment risks.

Infra & supply chain

Root-user Dockerfiles, exposed database ports, missing lockfiles, risky dependencies, and CI secret leaks.

Cloud, crypto & auth flows

Public Terraform S3 buckets and open security groups, weak token randomness, missing JWT expiry, OAuth CSRF, and unauthenticated WebSocket handlers.

Judgment-based review in Claude Code

The /audit-saas-review skill ships with the package. It reviews your code against the same rule catalog, traces auth and data paths across files, and double-checks each finding before reporting it.

Today, and where it's headed

AuditSaas is built stack-first, not language-first — full depth on the JavaScript/TypeScript SaaS stack today, with broader language and platform coverage planned as community feedback prioritizes it.

  • JavaScript & TypeScript — Node.js, Next.js, Remix, Express, Fastify, Hono
  • Frontend frameworks — React, Vue, Svelte/SvelteKit, Astro, including .vue/.svelte/.astro files
  • Databases & ORMs — Prisma, Drizzle, Supabase, Postgres, MySQL, MongoDB
  • Infra as code — Docker, Docker Compose, Terraform

On the roadmap, prioritized by community demand:

  • Python, Java, Kotlin, Swift, Rust, Go
  • Android & iOS mobile app checks
  • Cloud deployment configs beyond Terraform (Pulumi, CDK, CloudFormation)
  • Real dependency CVE lookup, not just pattern-based checks

Get started in under a minute

Open source and free to run. Point it at any project — it reads your code, writes Markdown and JSON reports into your repo, and does nothing else.

  • Works on any JavaScript/TypeScript codebase — Node.js, Next.js, React, Vue, Svelte, and more — no config required
  • Optional second-pass AI review with your own API key
  • Full reports written straight into your project
npx auditsaas scan .

# or, to contribute:
git clone https://github.com/sagaragarwal94/audit-saas
cd audit-saas && npm install && npm test

# focus on one category
saas-audit scan . --focus security
saas-audit scan . --focus privacy
saas-audit scan . --focus payments
saas-audit scan . --focus ai

# list every rule
saas-audit rules

Gate every PR in CI

Add one job and AuditSaas runs on every push. It fails the build on the severities you choose, and findings show up in GitHub's Security tab.

  • --fail-on high exits non-zero on high or critical findings
  • SARIF with stable fingerprints, so alerts track across runs instead of duplicating
  • --baseline fails only on new findings, so you can adopt it on an existing codebase today
  • Silence a reviewed finding with // auditsaas-ignore RULE_ID -- reason or .auditsaas.json. It stays listed in the report.
# .github/workflows/auditsaas.yml
name: AuditSaas
on: [push, pull_request]
permissions:
  contents: read
  security-events: write
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - uses: actions/setup-node@v5
        with:
          node-version: 24
      - run: npx auditsaas@latest scan . --no-history --fail-on high
      - if: always()
        uses: github/codeql-action/upload-sarif@v4
        with:
          sarif_file: audit-output/findings.sarif.json

Optional AI review — your key or a local LLM

The deterministic scanner needs nothing external. If you want a second-pass AI review of the findings, point it at any OpenAI-compatible endpoint — a hosted provider with your own API key, or a fully local model like Ollama or LM Studio. Nothing runs unless you opt in.

  • Bring your own OpenAI/Anthropic-compatible API key
  • Or point AUDITSAAS_LLM_BASE_URL at a local model server
  • Sends only compact, redacted finding context — never full source
  • Time-limited, and a failed review never blocks the deterministic reports
  • --no-ai-review skips it entirely
# Hosted provider with your own key
export AUDITSAAS_LLM_API_KEY=your-provider-key
export AUDITSAAS_LLM_MODEL=your-model-id
export AUDITSAAS_LLM_BASE_URL=https://api.openai.com/v1

# Or a local model server (Ollama, LM Studio, etc.)
export AUDITSAAS_LLM_BASE_URL=http://localhost:11434/v1
export AUDITSAAS_LLM_MODEL=llama3.1

saas-audit scan . --out-dir ./audit-output
