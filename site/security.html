Security

Security & responsible disclosure

Last updated: July 2026

Reporting a vulnerability

If you find a security issue in the AuditSaas CLI, in this website, or in how the beta is distributed, please report it privately to security@auditsaas.org before disclosing it publicly. Include:

  • What you found and where (CLI, website, a specific rule, the install package)
  • Steps to reproduce, or a proof of concept
  • What you think the impact is

We'll acknowledge reports within a few business days and keep you updated as we investigate and fix the issue. We ask that you give us reasonable time to fix a confirmed issue before any public disclosure.

What's in scope

  • The AuditSaas CLI source and its distributed install package
  • auditsaas.org (this website)
  • The beta waitlist form and invite/distribution process

What's out of scope

  • False positives/negatives in scan results — please report those to beta@auditsaas.org instead, as product feedback rather than a security report.
  • Third-party services we rely on (Tally, Vercel, Cloudflare) — please report those directly to the respective provider.

A note on trust

AuditSaas runs locally against your codebase, so we take its own security seriously — a vulnerability in the tool itself would undermine the reason to use it. If you're auditing the CLI's source as part of your own due diligence before running it, we'd genuinely like to hear what you find, positive or negative.

Machine-readable disclosure

A /.well-known/security.txt file (RFC 9116) is also published for automated tooling.
